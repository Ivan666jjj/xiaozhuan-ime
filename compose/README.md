# compose —— 部件反查输入法

输入**部件序列**，反查以这些部件构成的小篆字。

```
敲「水工」 →  江（输出《说文》真篆形 U+3EF65）
敲「日木」 →  杲 / 杳 / 果
敲「月囧」 →  朙（这个才是「明」的小篆本字）
```

## 为什么是「反查」而不是「合成」

一开始的想法是「540 部拼出不存在的字」，但实测后发现**拼字这条路有系统性错误**：

| 字 | 楷书部件结构 | 《说文》小篆构形 |
|---|---|---|
| 明 | `日 + 月` | **`月 + 囧`**（根本没有「日」） |
| 香 | `禾 + 日` | `黍 + 甘` |
| 射 | `身 + 寸` | `矢 + 身` |
| 春 | `𡗗 + 日` | `艸 + 日 + 屯`（三层） |
| 年 / 及 | 楷书是**独体** | `禾 + 千` / `又 + 人`（拆得开） |

三层障碍：

1. **「文」≁「字」**。《说文解字叙》：「依类象形，故谓之文；形声相益，即谓之字」。
   540 部就是「文」，是原子，本身拼不出来。
2. **省形省声**。《说文》大量标注「从某省」「某省声」（如「夜」从夕、亦省声），
   机械拼接会把省掉的部件又加回去。
3. **最致命**：IDS 描述的是**楷书**结构。楷书经隶变、简化后，部件切分已与小篆脱节。
   拿小篆部件去拼楷书结构，是**系统性张冠李戴**。

所以本项目**只做反查**：部件码只是**输入的键**，输出的永远是**查得到的真篆形**。
字形合成一行代码都没有，也就不存在「拼出来的假篆字冒充真篆字」的问题。

## 文件

| 文件 | 作用 |
|---|---|
| `decompose.py` | 读 IDS，把字拆成部件（偏旁归一、去笔画、独体返回空） |
| `build_index.py` | 建反查索引 `index.json` |
| `lookup.py` | 查询（精确匹配 + 子集匹配） |
| `cli.py` | 命令行入口 |
| `radical_alias.json` | 楷书偏旁 → 正字（`氵→水`、`亻→人`…） |
| `radical.py` | 540 部检索：按《说文》部序查字 |
| `radical_index.json` | 540 部及其所辖字（从 SealSources 的 `kSEAL_Rad` 提取） |
| `ids.txt` | 汉字部件拆解数据（40,207 条） |
| `SPEC.md` | 交给模型实现的规格（本项目由 `ds-flash` 按此实现） |

## 用法

```bash
python3 compose/cli.py --build        # 建索引（改了数据后要重跑）
python3 compose/cli.py 水工            # 查询
python3 compose/cli.py --json 日木     # JSON 输出
python3 compose/cli.py --explain 沐    # 看某字的部件
```

## 数据依赖

- `../data/seal_index.json` —— 有篆形的字表（12,836 字）
- `../data/char_to_seal.json` —— 字 → 小篆字符（13,658 条）

## 已知局限

- **部件码依据楷书 IDS，不是《说文》构形**。所以敲「日月」会出「明」——
  作为**输入编码**这是对的（符合现代人的直觉），但**别据此判断小篆结构**。
  研究古文字请以《说文》原文为准。
- 「部件码」是**无序集合**，`水工` 与 `工水` 等价；同一组部件不同排列的字
  （杲/杳）会一起列为候选，需要用户自己选。
- 繁体部件（`魚`/`頁`/`軍`）篆形覆盖较薄，因为补区字表来自简体词表。
